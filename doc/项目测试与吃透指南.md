## 一、必须懂的 3 件事

### 1. 这个项目是什么

基于 `epoll` 的主从 Reactor 网络库：**主线程只负责 accept 新连接，工作线程各跑一个 EventLoop 处理读写**。

面试官问："为什么主线程只 accept？"
你要能答：accept 本身是很轻的系统调用。如果主线程还兼做读写，accept 会被长耗时的读写拖慢，新连接建立延迟上升。独立出来保证新连接及时建立。

面试官问："为什么每个工作线程独立跑一个 EventLoop？"
你要能答：共享一个 EventLoop 就要对同一个 epoll 实例和任务队列加锁，锁竞争成瓶颈。每个线程独立一个，连接分配给谁就永久归谁管，全程不用加锁。

### 2. `recv()` 返回 0 是什么意思

**对端关闭了连接（发了 FIN）。不是"暂时没数据"——那是 EAGAIN。**

这是你修复的核心之一。原代码把这两种情况都归成同一个返回值 0，于是对端正常关闭时，连接既不被释放、也不关闭，fd 停在"可读但读不到数据"的状态被 epoll 反复通知，事件循环空转。

面试官问："这个 bug 具体什么现象？"
你要能答：客户端正常断开后，服务端不回收连接，而且 CPU 会往上跑。因为 fd 处于 EOF 状态，LT 模式下 epoll 每次都通知可读，读又读不到东西。

### 3. `Content-Length: abc` 为什么能把服务器搞崩

原代码直接调 `std::stol` 解析这个头，**没有 try/catch**。输入非法时 `std::stol` 抛 `std::invalid_argument`，一路上没人接住，程序直接 `std::terminate`——**整个服务进程死掉**。一条畸形请求就是一个进程级 DoS。

修复：手写解析，只接受纯数字；同时拒绝负数（转 `size_t` 会变成超大值）和超长数字；再对正文长度设上限，超了返回 413。

面试官问："这个 bug 是你写的还是原有的？"
**照实答：教程代码就存在，我是审查时发现的。** 这个项目是我照着 muduo 的设计思想逐个模块实现的，架构不是我原创——但缺陷是我定位并修复的。主动承认比硬撑有利得多，面试官会认为你诚实且真动过手。

## 二、怎么跑通

必须在 Linux（VMware 虚拟机）。Windows 和 MinGW 编译不了——项目依赖 `epoll` / `eventfd` / `timerfd`。

```bash
sudo apt install -y build-essential wrk      # 一次性

cd source/echo && make && ./main              # 监听 8500
cd source/http && make && ./main              # 监听 8085，必须在 source/http 下运行
```

```bash
echo hello | nc 127.0.0.1 8500                          # echo
curl -i http://127.0.0.1:8085/hello                     # 动态路由
curl -i http://127.0.0.1:8085/index.html                # 静态文件
```

常见报错：

| 现象 | 原因 |
|---|---|
| `server.hpp: No such file` | 不在 `source/xxx` 下执行 make，或 `-I../../include` 被删了 |
| `assert(IsDirectory(path))` 失败 | http 服务不在 `source/http` 下运行，找不到 `./wwwroot/` |
| 端口被占 | 上次的 `./main` 没退干净：`pkill -x main` |

## 三、怎么验证改动

```bash
bash test/run_checks.sh
```

脚本依次做：构建两个示例 → 跑单元测试 → 起服务 → 测 `GET /hello` → 发 4 种畸形 `Content-Length` 看进程是否存活 → 测客户端断开后连接是否回收、CPU 是否空转。

**重点看第 2 步**。`recv()==0` 那个缺陷不是必现的（原实现依赖残留的 `errno` 值），所以单测先故意制造一次 EAGAIN 再让对端半关闭，**确定性地**复现：

```
case 3: [PASS] 对端半关闭返回 -1(EOF)，与 case 1 的 0 区分开      <- 修复后
case 3: [FAIL] ...                                              <- 修复前
```

想看修复前的表现：

```bash
git stash && bash test/run_checks.sh ; git stash pop
```

修复前第 5 步的"非数字 Content-Length"会直接干掉 http 进程，后续用例全部报"服务进程已不在"——这是预期现象。

## 四、怎么出简历数字

```bash
nproc ; free -m | head -2     # 记下核数和内存，写简历要用
bash test/bench.sh
```

简历上这样写：

```
单机 <N> 核 <M>G VMware 虚拟机，wrk -t2 -c<并发> -d15s 压测：
QPS 约 <X>，P99 约 <Y> ms
```

**几千 QPS 也照写。** 实习面试官看的是"你会测、读得懂数据"，不是数字大小。数字虚高反而会在"你怎么测的"这一问露馅。
